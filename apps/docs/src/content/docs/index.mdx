## Why another database client?

Nembrix is built for engineers who keep three connections open while
shipping a migration. It treats sessions, schemas, and tabs as first-class
state, and gets out of the way once you're actually editing rows — free,
open source, native, and Postgres-first.

<div class="feature-grid">
  <div class="feature-card">
    <h3>Multi-session rail</h3>
    <p>Multiple live sessions per saved connection, drag-to-reorder, recent connections in one click.</p>
  </div>
  <div class="feature-card">
    <h3>SSH first</h3>
    <p>Native russh tunnels with password / key / agent auth and TOFU host verification.</p>
  </div>
  <div class="feature-card">
    <h3>Editable grid</h3>
    <p>Double-click a cell, edit, ⌘S commits every pending change in one transaction. Right-click for copy / set&nbsp;NULL.</p>
  </div>
  <div class="feature-card">
    <h3>JavaScript scripting</h3>
    <p>Write JS with <code>await db.query(...)</code>, loops, and <code>console.log</code> over a live SQL connection — sandboxed, with a timeout &amp; cancel.</p>
  </div>
  <div class="feature-card">
    <h3>Real EXPLAIN ANALYZE</h3>
    <p>Heat-colored plan tree, per-node cost or actual time, hot branches surface instantly.</p>
  </div>
  <div class="feature-card">
    <h3>Schema tools</h3>
    <p>Structure pane, schema diff with a migration preview, ER diagram, and a role / grant matrix.</p>
  </div>
  <div class="feature-card">
    <h3>Copy between connections</h3>
    <p>Move a table — or a whole database — from one live connection to another with FK ordering handled for you.</p>
  </div>
  <div class="feature-card">
    <h3>Private by default</h3>
    <p>Cross-platform (macOS / Windows / Linux). No required cloud account, no telemetry, no daemon.</p>
  </div>
</div>
